# Telegram-бот для записи в парикмахерскую «Народная цирюльня»

## Описание проекта

Telegram-бот для автоматизации записи клиентов в парикмахерскую «Народная цирюльня».

Бот позволяет клиентам самостоятельно записываться к мастерам через Telegram, просматривать доступное время и получать подтверждение записи без участия администратора.

Для сотрудников предусмотрены административные команды управления мастерами, расписанием и записями клиентов.

Бот разработан на Python с использованием библиотеки Aiogram и базы данных SQLite.

## Возможности

### Для клиентов

* Выбор услуги.
* Выбор мастера, который выполняет выбранную услугу.
* Просмотр доступных дат и времени.
* Онлайн-запись к мастеру.
* Получение подтверждения записи.
* Удобный интерфейс через Telegram.

### Для администратора

* Добавление новых мастеров.
* Добавление новых услуг.
* Настройка рабочего расписания.
* Управление ручными выходными и праздничными датами.
* Просмотр записей клиентов.
* Управление расписанием мастеров.

## Установка и запуск

### 1. Клонирование репозитория

```bash
git clone https://github.com/Maksim-1995/tg_bot_for_barber.git
cd tg_bot_for_barber
```

---

### 2. Создание виртуального окружения

Linux/macOS:

```bash
python3 -m venv venv
source venv/bin/activate
```

Windows:

```powershell
python -m venv venv
venv\Scripts\activate
```

---

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

---

### 4. Настройка переменных окружения

Создайте файл `.env` по примеру файла `.env.example`.

Пример:

```env
BOT_TOKEN=your_telegram_bot_token
ADMIN_IDS=123456789
DATABASE_URL=sqlite+aiosqlite:///data/database.db
```

Если администраторов несколько, укажите ID через запятую:

```env
ADMIN_IDS=123456789,987654321
```

---

### 5. Запуск проекта

```bash
python bot.py
```

После успешного запуска в консоли появится сообщение:

```text
База данных инициализирована
Бот запущен и готов к работе
```

```bash

```

## Административные команды

Команды доступны только администраторам из `ADMIN_IDS`.
Большинство команд можно запускать без аргументов — бот откроет пошаговый диалог с подсказками и кнопками.
Любой админский диалог можно прервать командой `/cancel` или кнопкой «Отменить настройку».

### Главное меню администратора

```text
/admin
```

Открывает кнопочную админку с разделами: услуги, мастера, расписание, записи и выходные даты.
Через это меню можно запускать все основные админские сценарии без ручного ввода команд.
После завершения действия бот показывает кнопки возврата в текущий раздел или в главное меню админки.
Если администратор нажмёт старую кнопку из неактуального сообщения, бот покажет предупреждение и предложит открыть раздел заново.
Повторные быстрые нажатия на подтверждение, перенос или финальное сохранение защищены от дублей.

---

### Добавление услуги

```text
/add_service
```

Бот попросит название услуги и длительность в минутах.

Быстрый вариант:

```text
/add_service Детская стрижка 45
```

---

### Добавление мастера

```text
/add_master
```

Бот попросит имя, описание и предложит выбрать услуги кнопками.

Быстрый вариант:

```text
/add_master "Анна Иванова" "Стаж 5 лет" 1,2
```

---

### Просмотр услуг и мастеров

```text
/list_services
/list_masters
```

Показывает ID, которые нужны для настройки мастеров и расписания.

---

### Редактирование услуг и мастеров

```text
/edit_service
/edit_master
```

`/edit_service` позволяет изменить название, длительность, отключить или включить услугу.
Отключённая услуга остаётся в базе и старых записях, но не показывается клиентам.

`/edit_master` позволяет изменить имя, описание, список услуг, отключить или включить мастера.
Отключённый мастер остаётся в базе и старых записях, но не показывается клиентам.

---

### Настройка расписания

```text
/set_schedule
```

Бот предложит выбрать мастера, день недели, тип дня и рабочие часы.

Быстрый вариант:

```text
/set_schedule 1 0 10:00 20:00 14:00 15:00
```

Используется для создания и изменения расписания работы мастеров.
День недели задаётся числом: 0=ПН, 6=ВС.

---

### Регулярный выходной мастера

```text
/set_day_off
```

Открывает тот же диалог настройки расписания, где можно выбрать выходной.

Быстрый вариант:

```text
/set_day_off 1 6
```

Отмечает день недели как нерабочий для выбранного мастера.

---

### Праздничные и ручные выходные даты

```text
/add_closed_date
/remove_closed_date
```

`/add_closed_date` попросит дату и необязательную причину.
`/remove_closed_date` покажет список закрытых дат кнопками.

Быстрые варианты:

```text
/add_closed_date 31.12.2026 Новый год
/list_closed_dates
/remove_closed_date 31.12.2026
```

Закрытые даты не показываются клиентам при выборе свободного времени.

---

### Просмотр записей

```text
/view_bookings
```

Показывает список всех записей клиентов.

---

### Ручное создание записи

```text
/create_booking
```

Запускает пошаговый диалог для администратора: услуга, мастер, дата, время, имя клиента, телефон и комментарий. Подходит для клиентов, которые записались по телефону или на месте без Telegram.

---

### Управление записями

```text
/manage_bookings
```

Показывает будущие активные записи кнопками. Администратор может выбрать запись, перенести её на другой свободный слот или технически отменить. Отменённая запись остаётся в базе, но больше не занимает время мастера.

## Пользовательский сценарий

1. Клиент открывает бота.
2. Нажимает «Записаться».
3. Выбирает услугу.
4. Выбирает мастера.
5. Выбирает дату и свободное время.
6. Вводит имя, телефон и необязательный комментарий.
7. Подтверждает запись.
8. Информация сохраняется в SQLite, администратору приходит уведомление.

Если клиент нажмёт старую кнопку выбора услуги, мастера, даты, времени или подтверждения, бот покажет предупреждение и предложит начать запись заново.

## CI/CD

Проект поддерживает автоматический деплой через GitHub Actions.

После каждого пуша в ветку `main`:

1. Собирается Docker-образ.
2. Образ публикуется в Docker Hub.
3. Выполняется обновление контейнера на сервере.

## Резервное копирование базы

SQLite-база хранится в `data/database.db`. Для Docker-запуска директория `data` должна быть подключена как volume.

Пример локального backup:

```bash
cp data/database.db "data/database-$(date +%Y-%m-%d).db"
```

Пример backup на сервере из volume:

```bash
cp ~/barber_bot_data/database.db ~/barber_bot_data/database-$(date +%Y-%m-%d).db
```

## Типовые проблемы

### Бот не отвечает

Проверьте, что контейнер запущен:

```bash
docker ps
docker logs -f barber_bot
```

### Админ-команды не работают

Проверьте, что Telegram ID администратора указан в `ADMIN_IDS`.

### После деплоя пропали записи

Проверьте, что контейнер запущен с volume:

```bash
-v ~/barber_bot_data:/app/data
```
